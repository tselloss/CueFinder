## Emergency Procedures

### Database Corrupted
```bash
# 1. Stop services
docker compose stop backend-blue backend-green moderator

# 2. Restore latest good backup
./manage-backups.sh restore /home/cuefinder/backups/cuefinder_backup_YYYYMMDD_HHMMSS.sql

# 3. Verify restore
docker exec cuefinder-postgres psql -U postgres -d cuefinder -c "SELECT COUNT(*) FROM users;"

# 4. Restart services
docker compose up -d backend-blue backend-green moderator
```

### Data Lost After Migration
```bash
# The system automatically detects and prevents this
# But if you need to manually restore:
docker compose stop backend-blue backend-green moderator
./manage-backups.sh restore /home/cuefinder/backups/cuefinder_backup_<BEFORE_MIGRATION>.sql
docker compose up -d backend-blue backend-green moderator
```

### Need to Verify Backup Before Restore
```bash
./manage-backups.sh verify /home/cuefinder/backups/cuefinder_backup_YYYYMMDD_HHMMSS.sql
```

## What Gets Backed Up

### Critical Data (ALWAYS protected)
- ✅ All user accounts and profiles
- ✅ Forum categories and posts
- ✅ Billiard cue inventory
- ✅ Case information
- ✅ User ratings and reviews
- ✅ All uploaded images

### What Happens on Migration
```
1. Create backup (automatic)
2. Verify backup (automatic)
3. Count critical records (automatic)
4. Run migration
5. Count critical records again (automatic)
6. Compare: if records decreased → rollback (automatic)
7. Complete
```

**If data loss is detected, the system automatically restores from backup.**

## Backup Schedule

### Automatic (Scheduled)
- **When**: Every day at 2 AM (configurable)
- **What**: Full database dump
- **Retention**: Last 30 backups kept
- **Storage**: `/home/cuefinder/backups/`

### Before Deployments
- **When**: Before every infrastructure deployment
- **What**: Full database dump
- **Verification**: Tested immediately after creation
- **Rollback**: Automatic if migration fails

### Manual
- **Command**: `./manage-backups.sh backup`
- **On-demand**: Anytime before risky changes

## Backup File Information

### Location
```
/home/cuefinder/backups/cuefinder_backup_YYYYMMDD_HHMMSS.sql
```

### Size
- Typical: 5-50 MB (compressed: 1-10 MB)
- Depends on number of users and posts

### Age
- Fresh: created today
- Stale: older than 7 days (should backup more often)
- Very old: older than 30 days (will be deleted by cleanup)

### Verification
```bash
# Check if backup is valid and restorable
./manage-backups.sh verify <backup_file>

# Expected output: "Backup is valid and restorable"
```

## Restore Process Safety

### What Happens During Restore
1. Create safety backup of current database
2. Stop application services
3. Restore from backup file
4. Verify restore success
5. Restart application services
6. Confirm services are healthy

### Safeguards
- ✅ Confirmation required (must type "yes")
- ✅ Safety backup created first (can undo restore)
- ✅ Services stopped during restore (no conflicts)
- ✅ Automatic rollback if restore fails

## Storage & Cleanup

### Current Backup Size
```bash
du -sh /home/cuefinder/backups/
# Example: 150M (30 backups × 5MB each)
```

### Compression
- Old backups (>7 days) automatically compressed
- Saves ~80% storage space
- Can still be restored without decompressing

### Auto-Cleanup
```bash
# Keep only last 30 backups
./manage-backups.sh cleanup

# Manual cleanup (older than 30 days)
find /home/cuefinder/backups -name "*.sql" -mtime +30 -delete
```

## Troubleshooting

### "Backup file is empty"
**Cause**: Database didn't export properly
**Fix**: Try again, or check if PostgreSQL is running
```bash
docker ps | grep postgres
```

### "Restore failed"
**Cause**: Backup might be corrupted
**Fix**: Use safety backup, or try older backup
```bash
./manage-backups.sh list
./manage-backups.sh verify <older_backup>
```

### "No backups found"
**Cause**: First time setup or cleanup deleted too many
**Fix**: Create a backup now
```bash
./manage-backups.sh backup
```

### "Backup verification failed"
**Cause**: Backup is incomplete or corrupted
**Fix**: Delete and create new backup
```bash
rm /home/cuefinder/backups/corrupted_backup.sql
./manage-backups.sh backup
```

## Production Deployment Before Using

### Setup Required (One-time)
```bash
ssh cuefinder@<SERVER_IP>

# 1. Create backups directory
mkdir -p /home/cuefinder/backups

# 2. Create scripts directory
mkdir -p /home/cuefinder/scripts

# 3. Copy manage-backups.sh
cp manage-backups.sh /home/cuefinder/scripts/
chmod +x /home/cuefinder/scripts/manage-backups.sh

# 4. Copy verify script
cp verify-database-integrity.sql /home/cuefinder/scripts/

# 5. Create initial backup
./manage-backups.sh backup

# 6. Verify backup works
./manage-backups.sh list
```

### Enable Daily Automated Backups
```bash
# Add to crontab
crontab -e

# Add this line (backup daily at 2 AM):
0 2 * * * /home/cuefinder/scripts/manage-backups.sh backup

# Verify cron was added
crontab -l
```
